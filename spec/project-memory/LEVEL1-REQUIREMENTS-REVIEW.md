# 第一层项目记忆需求审查记录

- 审查对象：`LEVEL1-REQUIREMENTS.md`
- 审查轮次：1
- 结论：通过，问题已纳入需求规格 1.0

## 1. 审查方法

本次审查从一致性、可验证性、边界、失败恢复、安全、长任务质量和现有架构兼容性七个方向检查需求。每个问题必须有明确处理结果，不能只记录风险。

## 2. 已发现并修订的问题

### R1 SQLite 与 JSONL 可能形成双重权威

- 问题：如果 SQLite 和事件 JSONL 都能独立决定当前状态，崩溃后可能产生分叉。
- 修订：SQLite 是结构化状态唯一权威；会话 JSONL 保存原始消息；事件 JSONL 是 SQLite outbox 的审计镜像。
- 对应需求：PM1-STO-001～003。

### R2 “每轮总结”可能无限总结旧摘要

- 问题：滚动摘要会放大模型错误和遗漏。
- 修订：每轮保存结构化 delta；状态摘要可从原始事件和结构化状态重建，不递归依赖旧摘要。
- 对应需求：PM1-TURN-003～005。

### R3 模型可能直接声称任务完成

- 问题：助手文本或模型 JSON 不能证明客观任务完成。
- 修订：公共更新 API 禁止写 `done`；只有确定性完成门可以写入。
- 对应需求：PM1-TASK-004、PM1-VAL-006。

### R4 任务可能没有可执行校验

- 问题：“所有校验通过”在空校验集合上会错误得到真。
- 修订：任务创建必须包含至少一个必需校验项；空计划拒绝。
- 对应需求：PM1-VAL-001。

### R5 校验证据在任务修改后仍被复用

- 问题：代码或验收条件变化后旧测试结果可能失效。
- 修订：任务和来源变化增加 revision，旧证据转 stale，已完成任务转 needs_review。
- 对应需求：PM1-TASK-007、PM1-SRC-003。

### R6 父任务可能早于子任务完成

- 问题：只检查父任务自身校验会遗漏未完成子任务。
- 修订：所有有效子任务必须完成后父任务才能完成。
- 对应需求：PM1-TASK-005、PM1-VAL-006。

### R7 模型任意百分比会制造虚假精度

- 问题：“进度 80%”通常没有可验证依据。
- 修订：权威进度由步骤、校验和任务状态派生；模型百分比仅可作为非权威说明。
- 对应需求：PM1-TASK-006。

### R8 多会话会静默覆盖状态

- 问题：不同 session 可能基于旧状态同时写入。
- 修订：所有状态变更采用 base revision compare-and-set。
- 对应需求：PM1-STATE-003、PM1-REC-004。

### R9 模型写回失败可能丢失本轮

- 问题：结构化提取是额外模型调用，可能超时或返回非法 JSON。
- 修订：原始会话先由现有 ProjectStore 保存；项目记忆保存最小检查点并标记 needs_reconcile。
- 对应需求：PM1-TURN-004、PM1-NFR-001。

### R10 内存 Resume 重启丢失

- 问题：现有 `_resume_state` 只在进程内存在。
- 修订：按 project/session 持久化完整工具调用 transcript，并定义消费与清理规则。
- 对应需求：PM1-REC-001～002。

### R11 外部路径暂时不可访问与删除混淆

- 问题：OneDrive 占位、移动盘离线和权限失败不等于文件已删除。
- 修订：来源状态区分 available、missing、changed、unreadable，并保留来源记录。
- 对应需求：PM1-SRC-002～004。

### R12 记忆补取可能无限调用模型

- 问题：模型可以反复请求更多历史，增加成本和延迟。
- 修订：每个用户请求最多两次；之后询问用户或报告阻塞。
- 对应需求：PM1-RET-004～006。

### R13 项目状态可能被通用上下文压缩丢失

- 问题：项目状态如果与普通支持材料一起压缩，当前任务和校验可能失真。
- 修订：项目状态使用独立保护标记和优先级；只有旧历史与证据可进入通用语义压缩。
- 对应需求：PM1-RET-003。

### R14 删除项目只删除目录，不删除 SQLite

- 问题：引入项目记忆表后现有目录删除会遗留结构化数据。
- 修订：删除流程必须同时删除 SQLite 项目记忆，再删除项目目录。
- 对应需求：PM1-REC-003。

### R15 证据中可能包含密钥

- 问题：工具参数和输出进入事件或证据时可能包含 secret/token。
- 修订：写入前复用统一敏感字段脱敏策略，密钥仅在 Vault。
- 对应需求：PM1-SEC-002～003。

### R16 “任务完成”与“实现完成”含义不清

- 问题：Agent 完成工作步骤不代表验收通过。
- 修订：拆分 implementation_complete、validating、validation_failed、awaiting_user_validation、done。
- 对应需求：PM1-TASK-002、PM1-VAL-007。

### R17 校验条件可能被 Agent 删除以规避失败

- 问题：模型可能修改验收计划以让完成门通过。
- 修订：校验计划变更必须形成事件、增加 revision 并使旧证据失效。
- 对应需求：PM1-VAL-008。

## 3. 边界覆盖检查

已覆盖：

- 新项目、已有项目、跨 session 和应用重启。
- 无任务、单任务、父子任务、并行任务。
- 空校验、失败校验、人工校验、过期证据。
- 模型失败、SQLite 失败、事件镜像失败。
- 重复请求、重复事件、revision 冲突。
- 超长历史和上下文压缩边界。
- 文件修改、移动、离线、不可读和删除。
- 项目删除和敏感信息。

## 4. 推迟到第二、三层的需求

以下不属于缺失，而是明确推迟：

- Embedding 生成和向量检索。
- RAG Provider、SaaS 凭据和远端删除。
- 分类路由索引。
- Graph 节点、边和跨分类联邦查询。
- OCR、ASR、视频关键帧等多模态索引。

## 5. 审查结论

没有未解决的阻塞性需求冲突。第一层可以进入函数级详细设计。实现阶段若发现必须改变 Must 行为，需要先更新需求和本审查记录，再修改设计或代码。
